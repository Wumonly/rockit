# 规范文档审查者提示模板

在派发规范文档审查子代理时使用此模板。

**目的：** 验证规范是否完整、一致且可供实现规划使用。

**派发时机：** 规范文档已写入 `docs/specs/` 后。

```
Task tool (general-purpose):
  description: "审查规范文档"
  prompt: |
    你是一名规范文档审查者。验证此规范是否完整并可供规划使用。

    **待审查的规范：** [SPEC_FILE_PATH]

    ## 检查项

    | 类别 | 检查内容 |
    |----------|------------------|
    | 完整性 | TODO、占位符、"TBD"、不完整的章节 |
    | 一致性 | 内部矛盾、冲突的需求 |
    | 清晰度 | 需求是否模糊到足以让人构建出错误的东西 |
    | 范围 | 是否足够集中以用于单个计划——不涵盖多个独立子系统 |
    | YAGNI | 未被请求的功能、过度设计 |

    ## 校准原则

    **仅标记那些会在实现规划中造成实际问题的缺陷。**
    缺少章节、矛盾之处、或模糊到可能被以两种不同方式解读的需求——这些才是问题。微小的措辞改进、风格偏好以及"某些章节不如其他章节详细"则不是问题。

    除非存在会导致计划缺陷的严重空白，否则批准。

    ## 输出格式

    ## 规范审查

    **状态：** 已批准 | 发现缺陷

    **缺陷（如有）：**
    - [章节 X]：[具体问题] - [为何重要]

    **建议（仅供参考，不阻止批准）：**
    - [改进建议]
```

**审查者返回：** 状态、缺陷（如有）、建议
