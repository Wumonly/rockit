# Brainstorming 命令

在动手写代码之前，通过结构化协作对话，将模糊想法转化为经过验证的设计方案。

## 执行

调用 `brainstorming` skill：

```
/skill brainstorming
```

## 流程

| 步骤 | 说明 |
|------|------|
| 1. 探索项目上下文 | 检查文件、文档、最近提交 |
| 2. 视觉伴侣 | 如果涉及视觉问题，单独提议浏览器伴侣工具 |
| 3. 提出澄清性问题 | 逐一提问，理解目标、约束和成功标准 |
| 4. 提议 2-3 种方案 | 说明权衡并给出推荐 |
| 5. 呈现设计 | 按复杂度缩放篇幅，逐部分获取批准 |
| 6. 编写设计文档 | 保存到 `docs/specs/YYYY-MM-DD-<topic>-design.md` |
| 7. 规范自审 | 检查占位符、矛盾、歧义、范围 |
| 8. 用户审查规范 | 批准后进入下一步 |
| 9. 过渡到实现 | 调用 writing-plans skill 创建实现计划 |

## 关键原则

- **一次只问一个问题** — 不要用多问题轰炸
- **严格执行 YAGNI** — 移除不必要功能
- **HARD GATE** — 设计方案获批前禁止任何实现动作
- **最终状态** — 调用 writing-plans，不直接进入实现

## 输出

`docs/specs/YYYY-MM-DD-<topic>-design.md` — 提交到 git 的设计规范文档。
